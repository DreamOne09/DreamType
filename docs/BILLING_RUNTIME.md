# 付款服務整合與管理監控

install_beta 可明確接受 BillingRuntime，購買路由、Google 通知與背景查驗共用同一個錄音 Store／SubscriptionPolicy。未提供 runtime 時仍為原邀請試用，不掛載付款路由；帶入政策仍要求事先完成離線資料庫準備，不能自動遷移。

Runtime 檢查商品目錄一致，啟動後預設每 30 秒執行一批付款查驗。關閉服務會先停止開始下一批並等待現有批次結束，再清理錄音工作。單筆外部查詢仍依驗證器逾時，尚須在正式部署設定憑證供應的期限。

管理端 /v2/admin/metrics 新增 billing 聚合資料：有效追蹤訂閱數、待確認數、過舊狀態、重試及連續失敗。工作停止、失敗、超過十分鐘未完成、至少五次失敗或綁定一小時尚未確認會列出提醒。數字不含帳號、購買憑證或供應商回應；仍由原管理金鑰保護。這是查詢介面的告警資料，不代表已建立離機推播監控。

付費模式下帳號建立只能給零試用分鐘，修改試用分鐘拒絕；允許停權／恢復。管理者不能用試用額度覆寫商品方案。未啟用付款模式時原管理流程維持不變。

測試在暫存資料庫中將 runtime 與 FastAPI 共用，驗證購買後 /v2/me 額度、管理 API 保護、背景啟停、關閉等待查驗，以及失敗狀態跨空批次仍可見；原偏好 ETag 更新也通過回歸。尚未接入正式主程式設定、Google 憑證、真實 Pub/Sub、商店付款或 Android 實機驗收，線上服務未啟用付款。

## 管理畫面

admin.html 依 billing_enabled 顯示試用或訂閱模式。付費帳號以文字顯示方案、有效／待查驗／衝突狀態及方案額度，停權儲存不傳 minutes；建立帳號傳零分鐘。管理畫面顯示待確認、等待查驗及重試數量與後端提醒。所有內容使用 textContent，通知文字不當作 HTML 執行。

check_admin_billing.py 使用實際瀏覽器與隔離 API，驗證付費與試用的建立／修改 payload、隱藏欄位、提示文字、HTML 注入防護與離開管理後無瀏覽器儲存。CI 已納入此驗收。未在正式付款環境或真實帳號測試。
