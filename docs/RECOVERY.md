# 0.5.0：斷線恢復與主機備份

## 手機斷線後

錄音已送達時，鍵盤會顯示排隊或辨識狀態。查詢結果遇到短暫網路錯誤／伺服器 5xx 時，最多連續重試三次；登入失效等 4xx 不重試。只重查工作，不重送錄音。

若等待失敗，或 App 被系統關閉，重新開啟鍵盤後選 **更多 → 取回上一筆**。會查詢目前帳號最近的一筆工作：還在處理就繼續等待；完成就顯示文字。取回必須手動確認插入，不會自動寫入新輸入框，也不會再扣額度。已經插入過的文字仍可取回，請自己確認是否重複。

若目前已有待插入文字，先插入或捨棄，才可取回上一筆。此功能限帳號模式；私人金鑰模式不保存工作索引。

**限制：** 原錄音必須已送達；結果只在主機記憶體保存約 15 分鐘。主機重啟、過期或原錄音根本未送達時無法恢復。這不是永久草稿保存，也不保證取回未送達的錄音。完成工作的用量不因重啟／結果過期而退回；中斷的未完成工作會釋放額度。

手機自動停止錄音的時間改為約 118 秒，為停止錄音與音訊封裝保留時間，降低碰到伺服器 120 秒上限的機會。裝置主執行緒長時間卡住等情況仍待實機測試。

## 不裝 App 也能管理帳號

用瀏覽器開啟「你的服務網址 + `/account`」，可登入、查用量、登出及輸入密碼刪除線上帳號。網址必須是管理者正在運行的主機，不能用 GitHub 網址代替。

網頁不把登入 token 寫入 localStorage/sessionStorage；登出會撤銷這次登入。刪除需再次輸入密碼並確認；主機管理者建立的私人備份不會因此自動改寫，需另外處理。臨時網址可變，尚不能視為正式商店的長期刪除網址。

## 備份家用主機

在專案根目錄執行：

```powershell
.\work\venv\Scripts\python.exe .\outputs\local_voice\backup.py create
```

SQLite 線上快照會寫入 `work/backups/beta-日期-隨機碼.zip`。包含帳號資料庫、管理者金鑰、原推論金鑰；**未加密，屬私人資料，不要上傳 GitHub**。不含錄音、逐字稿、模型、程式、通道設定或 Android 簽署憑證。簽署憑證須由維護者另行保管。

主機若要搬到 AI PC，先安裝程式與模型，在啟動服務之前，於新主機的專案根目錄執行：

```powershell
.\work\venv\Scripts\python.exe .\outputs\local_voice\backup.py restore --archive "D:\private-backups\你的備份.zip"
```

只允許恢復到空的 `work/beta`；若已有資料或推論金鑰不同，工具會拒絕覆蓋。不可為了通過檢查直接刪除既有使用者資料，請改用新的專案資料夾。

恢復會保留帳號、密碼雜湊、偏好及已成功使用量，撤銷全部舊登入，並將未完成工作標為失敗、釋放其額度。啟動後使用者重新登入；新通道網址需重新提供。原本帳號已刪除的舊備份可能重新帶回資料，恢復前需確認備份是否含應刪除資料；正式商用前仍需訂出備份保留與刪除政策。

## 驗證

- 16 項 Python 測試通過：新增最近工作隔離、重取不重扣、處理中取回、備份恢復、拒絕路徑穿越與覆蓋等驗證。
- Java 故障注入測試：503 後成功取回，沒有重送音訊；401 不重試。
- 相同 APK 連線類別已經 Cloudflare HTTPS 實際取回相同文字並檢查用量不變；不是 Pixel 9 實機測試。
- 手機尺寸瀏覽器通過登入、查用量、登出、錯密碼拒絕刪除、正確密碼刪除，無 JavaScript 錯誤。
- 已替目前主機建立私人快照，在另一個空白資料夾恢復，驗證帳號及偏好一致、登入已撤銷，原資料未改動。

仍待：Pixel 9 原生鍵盤／行動網路／Surfshark、中斷與大字體驗收、長時間負載、自動維運，以及 Google Play Billing 與上架。

## Android 空白結果保護（2026-09-22，0.9.2）

手機網路層現在要求回傳的 text 是字串，且至少包含一個非空白字元，才允許確認收件並返回成功。拒絕空字串、一般空白、全形空白、不換行空白、null、數字與物件。無效結果會進入既有錯誤路徑，不執行成功後的保留錄音清除；可依既有一小時期限重試。這不代表重新生成一定成功，也不延長伺服器結果的 15 分鐘期限。

`outputs/android/tests/EmptyResultCheck.java` 使用實際 VoiceApi.recover，對本機合成 HTTP 服務驗證六種無效回應均未觸發 receipt；正常中文回應成功且只確認一次。這是 JVM 網路路徑測試，不是 Pixel 9 或 Keystore 實機驗證。已打包到 0.9.2；0.9.1-rc1 不含此修改。

## 重試保留原本語言（0.9.2）

新錄音使用 DT2 加密格式，將模式、翻譯目標語言及來源語言放入 AES-GCM 加密內容。手機重試沿用保存的這三項設定，不讀取後來修改的語言；請求編號與音訊維持不變。翻譯重試結果仍須符合原目標語言，才確認收件。個人提示詞與詞庫仍使用伺服器接受請求時的偏好，這項修改不保證離線期間的所有帳號偏好都已快照。

舊 DT1 格式仍可辨識與讀取，但沒有原語言資料，因此不自動重傳。升級前有未完成錄音時，應先取回上一筆；若服務沒有結果，需刪除保留錄音後重新錄製。既有一小時期限及帳號隔離不變。

四組 JVM 合約測試通過，包含日文錄音在目前設定改為泰文後仍保留日文目標與 zh-TW 來源、DT2 防竄改、舊格式拒絕猜測、重試錯誤語言不確認收件。完整 APK 編譯、原簽章 v2/v3 驗證通過。Pixel 9 原機升級、Android Keystore 與斷線操作仍待實測。

## 突然退出與佇列容量驗證（2026-09-22）

`test_crash_recovery.py` 在獨立子程序與臨時 SQLite 資料庫測試三個退出點：錄音已保存且處理中、修改工作並刪除暫存但交易尚未提交、結果已完整提交。子程序直接 `os._exit`，不執行正常關閉；重新開啟後檢查資料庫完整性、保留錄音與語言、未提交交易回滾、已提交結果仍可讀取，以及重複收件不重扣額度。三個情境皆通過，並加入 CI。

這驗證程序突然退出後的已提交資料恢復，不模擬實體斷電、磁碟控制器快取遺失、硬碟故障或雲端還原。未中斷運作中的家用主機。

`test_beta.py` 另用實際 worker 配合一格測試佇列驗證：第一筆處理中、第二筆等待時，第三個帳號得到 429 且沒有使用／保留額度；佇列清空後，同一請求可成功提交。模型以可控的測試 provider 替代，這是容量邊界邏輯驗證，不是效能數據。
