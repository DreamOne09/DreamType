# 語音輸入，不代替使用者回答

DreamType 的整理模式只整理使用者口述內容。「請幫我生成一個計劃」應保留成這句要求，不能產生計劃。未加入代寫或執行助理模式。LLM 仍負責標點和排版；翻譯只有明確選擇翻譯模式時進行。

## 0.9.9 修正

- 辨識原文以 JSON transcript 資料欄位送入模型，系統指示明確限制口述及個人偏好不能要求模型作答或擴寫。
- 另檢查「請、幫我、please」等請求用語不得消失，避免只刪掉請求前綴就變成作答。整理後檢查文字變動量（忽略標點／空白）：新增最多原文 15%、刪除最多 30%，短句容許一字。超過時音訊 API 回傳完整辨識原文並顯示排版失敗提示；私人文字整理 API 回傳 503，避免替換原文。
- 這是保守的文字檢查，不是完整語意驗證。小幅但錯誤的改寫仍可能通過；大幅合理改寫則可能被退回。因此保留可人工還原的原文，不能宣稱永不改錯。
- Android 預覽新增「還原原文」，編輯頁新增「還原辨識原文」及「取消修改」。原文取自伺服器既有 raw_text；舊伺服器沒有原文時不冒充原文。翻譯也可還原來源辨識文字。
- 插入後新增「復原剛才輸入」，保留預覽並恢復原本被取代的選取文字。只在同一登入、同一輸入工作階段、游標位置與剛才插入內容一致時執行。改過文字／移動游標後不自動刪除；不支援提供不了必要 InputConnection 資訊的 App。
- 手機原文只保留於既有暫存記憶體，不寫入偏好、日誌或 Activity saved state；新錄音、捨棄與登入切換清除。帳號結果沿用伺服器加密 15 分鐘結果保存政策，沒有新增保存期限。

## 2026-09-26：否定與條件保護

後續補上有限的明確口述改口例外；「三點，不對，四點半」不再一概被否定保護拒絕，但「3 元，不是 4 元」的對比仍保留。原始辨識不修改，完整規則、限制及回歸證據見 [中文品質](CHINESE_QUALITY.md)。

僅限制字數變動無法擋住刪除一個「不」的錯誤。新增文字對齊檢查，當追蹤的否定／條件詞被刪除、插入、替換或移到別句時，整理回退原文。追蹤範圍見 dictation_guard.py 的 LOGIC；不等於完整語意理解。

原先三組人為破壞的輸出都能通過舊檢查，新版全部拒絕：[可重現比較](evidence/logic-guard/mutations.json)。這是驗證防護缺口，不能說是模型實際發生三次錯誤。音訊 API 測試亦確認「不要取消」被改成「要取消」時回傳原文與警示。

46 項本機相關測試通過。[8 組實際 Qwen 整理](evidence/logic-guard/live-formatting.json)包含條件、條列、重複口吃及改口。正常標點／條列、相鄰相同否定詞的口吃仍可清理；例如「不不不要取消」→「不要取消」。

取捨：同義改寫、部分同音字修正，或「不要取消，不對，是要取消」這類涉及否定的改口，可能保守回退完整原文，由使用者確認。未加入跨語翻譯檢查，也不保證未列出的邏輯詞、標點含義、數值或所有語意都正確。這些仍需持續補足，不能以通過本測試宣稱產品全面完成。


## 2026-09-26：數值、正負號與比例保護

整理前後另比對數字順序、正負號、小數與百分比／千分比，並保留數字尾隨的萬／億倍率。範例 `-1.5 → 15`、`5% → 5`、`12 人 → 13 人` 先前會通過改動幅度檢查，現在會回退原文。[三案模擬比較](evidence/numeric-guard/mutations.json)。

全形／半形、千分位、明確的正負字形與百分比寫法可等價對照；中文數量須有明確比例或支援的單位／量詞，例如 `3 次 ↔ 三次`、`一千五百元 ↔ 1500元`。共同數字解析器沿用翻譯原有規則，不猜「一千五」的簡寫值。連續多項清單編號視為排版，但項目內的人數、金額等仍核對順序。這不是計算、匯率、單位轉換或日期解讀服務。

52 項相關本機測試通過，音訊 API 亦驗證錯誤數值會回傳原文及警示。[7 組實際模型輸出](evidence/numeric-guard/live-formatting.json)包含數值、條列、時間與改口。其中模型真的將每次 `500 元` 寫成 `50及元`，被新檢查拒絕：[原始候選及回退證據](evidence/numeric-guard/observed-corruption.json)。其餘模擬錯誤不冒充實際模型錯誤。

限制：不是完整中文數字／單位／姓名解析。未支援的文字數字、日期改寫、範圍或同義轉換可能保守回退；中文數量也可能和地名／名稱混淆，不能據此宣稱地名及所有數值語意都已通過。原始辨識本身的錯字仍需 ASR、詞庫與實機資料改善。
