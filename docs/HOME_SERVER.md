# 家用主機部署決策

日期：2026-09-21。此決策更新先前「先測外部 API 作主服務」的建議；成本比較文件仍保留作未來參考。

## 最新確認方向

先讓手機都連到開發者家中的電腦，由這台電腦執行語音辨識與文字整理。未來可搬移到開發者的新 AI PC。暫時不採購或串接付費辨識／文字整理 API。

商店版「一般使用者不用開自己的電腦」的目標不變。需要保持開啟的是開發者的伺服器主機，而不是每位使用者的電腦。0.4.0 已加入邀請制多人帳號與排隊，尚無訂閱或公開商用服務。

## 已知硬體與能力

目前主機：Intel i7-9700、16 GB RAM、NVIDIA RTX 4060 Ti 8 GB。已跑通 Whisper Turbo 辨識與 Qwen 4B 文字整理；使用者確認過手機網頁流程速度可接受。

因此目前可繼續用於個人使用和小規模試用，沒有立即換機的必要。0.4.0 已以 1、2、3 個帳號同時提交短／長錄音跑通，約 29 秒錄音三筆最慢約 5.44 秒回傳，僅為 localhost 小樣本。新版 /v2 帳號 API 在 GPU 前加入單一工作佇列（2026-09-26 加入有限短整理優先，見 [容量與排程](CAPACITY.md)）；舊 /v1 私人 API 仍有五秒鎖等待限制。不要同時用舊 API 做大量工作，否則會影響帳號佇列。這不是多人商用容量承諾。

購買 AI PC 前需確認實際模型、NVIDIA/CUDA 或其他推論框架相容性、記憶體與顯示記憶體。單憑「AI PC」或 NPU TOPS 無法判斷比目前 4060 Ti 更適合這套軟體。

## 部署路線

手機 → 臨時 HTTPS 入口 → 已實作的帳號／權限與有限優先工作佇列 → 家用主機辨識與整理。使用者明確選擇先保留臨時通道，暫不購買網域。

已完成的登入、配額、隔離、排隊與小樣本速度驗證，見 [0.4.0 驗收](BETA_ACCEPTANCE.md)。公開商用前仍需：

- 固定網域／通道、服務自動啟動、主機睡眠與重啟恢復安排。
- 對目前邀請帳號系統進一步做長期安全、負載與帳號恢復驗證。
- 擴充工作恢復：現有請求代碼已防重複扣量，0.5.0 可從主機暫存取回最近結果，但主機重啟或结果過期仍無法取回。
- 用 1、2、3 個同時請求量測等待時間、失敗率、RAM／VRAM 使用量，再決定試用人數與承諾。
- 家用網路、停電或維修時的狀態提示；沒有備援時如實顯示暫時無法服務。

邀請登入已完成，收費系統仍需另外開發。家用主機不是已完成上架的替代證明；商店準備事項繼續參照 STORE_ROADMAP.md。

## 成本與未來替換

現有本機模型不收每次辨識的 API 費用，但仍有電费、網路、設備耗損及維護成本。電費應以實際整機量測為準：每月 kWh = 平均增量功率 W ÷ 1,000 × 運行小時，再乘實際適用電價。不要只用 GPU 標示功率推算整機費用。

維持 SpeechProvider／TextProvider 的替換方向：先以目前本機引擎作主實作，未來搬到 AI PC 或增加 Groq、Google、OpenAI 等服務時不必重做手機操作。外部 API 目前只是備選，不自動呼叫或收費。

換主機時遷移模型設定、work/beta 帳號資料庫與管理者金鑰與服務設定，妥善移轉密鑰，並盡量維持固定入口。現階段仍用臨時網址，換通道可能要重新配對。
