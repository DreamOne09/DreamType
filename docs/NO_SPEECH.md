# 沒有辨識出語音時的提示

0.9.17／新版主機：原本三秒靜音從私人 API 得到 200 與空白文字。現在辨識原文為空白時，回傳 422 與固定 no_speech 錯誤碼，不呼叫整理或翻譯。手機只對這個狀態碼和錯誤碼組合顯示確認麥克風並重新錄音；503 等故障仍顯示連線問題。

帳號工作仍是 failed，不計入用量，也不佔預留額度。固定失敗原因使用現有加密 results 表保留 15 分鐘，刪除伺服器 pending audio；重啟後可取回同一原因，過期後退回一般失敗提示。明確重試同一工作時清除舊結果，避免帶入上一輪原因。不需要資料庫欄位遷移。手機原有手動保留錄音／重試機制不變，不自動重送。

只有受信任的 provider 明確提出 422/no_speech 才使用此原因；空白／格式錯誤的 provider 回應仍是一般失敗，不能假裝知道錄音內容。這不代表 ASR 能正確判斷所有背景音，也不能保證沒有幻聽文字。

## 驗證

- 新測試涵蓋私人 API 空白及全形空白、跳過 formatter、釋放 GPU 鎖、provider 狀態配對、加密原因、跨帳號拒絕、重啟後讀取、重試清除、伺服器錄音刪除與零計費。
- [真實本機 ASR](evidence/no-speech.json)：三秒數位靜音、翻譯模式靜音及固定種子的低振幅雜訊。私人 API 全為 422/no_speech；隔離帳號 API 透過正式 LocalProvider 與主機模型處理後均為 failed、used/reserved 為零。沒有使用私人錄音或修改正式帳號。這不是全面噪音或真人語音測試。
- Android JVM 對固定錯誤碼顯示中文提示，錯誤狀態配對不符仍使用一般連線提示。[原生工作 36430822694](https://github.com/DreamOne09/DreamType/actions/runs/36430822694) 於功能提交 c8da2b2 通過（6 分 29 秒），四條既有键盤流程、跨程序錄音及編輯建議回歸通過。這不是新靜音提示的 Pixel 9 UI 驗收；靜音處理由 JVM、API 與真實主機 ASR 分別驗證。
- 完整本機 163 項測試與 GitHub 全探索測試通過。0.9.17-rc1 公開 APK 維持原簽章、versionCode 27，公開下載 SHA256 為 ff3ee580c5faf7add4a730a5230f613d4aa1061c8c8be44559371165d5914998。

需安裝 0.9.17 才有私人連線模式的新錯誤提示；帳號模式可由新版主機提供訊息。Pixel 9／Surfshark 與實際重新錄音仍待驗收。
