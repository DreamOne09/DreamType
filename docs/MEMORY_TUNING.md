# Qwen 載入方式與家用 RAM：2026-09-28

已將 Qwen 的啟動參數改為 `--load-mode none`。本機與安裝腳本均使用 llama.cpp build 11055；本機 CLI 明確支援此參數。模型檔案、量化、GPU 層數、context 4096、單工作槽與文字生成設定不變。TranslateGemma 與正式 Turbo 辨識模型不變，不需要更新手機 APK。

先停止原 gateway／Qwen，保留 TranslateGemma；用新載入方式啟動相同 Qwen，再保持兩者常駐執行相同的 Breeze 96 段短句及 18 次文字請求。測試後先恢復原配置，確認結果後才將此載入方式套用至正式服務。

| 觀察項目 | 原載入方式共存測試 | Qwen load-mode none |
|---|---:|---:|
| 最低可用系統 RAM | 25.5 MiB | 2,518.7 MiB（約 2.46 GiB） |
| 觀察 GPU 最高用量 | 7,621 MiB | 7,584 MiB |
| Breeze 辨識中位時間 | 0.351 秒 | 0.351 秒 |
| 整理／日英翻譯請求 | 18/18 完成 | 18/18 完成 |

新方式的 Qwen 啟動約 2.59 秒，啟動後 RSS 約 703 MiB。兩輪測試前系統可用 RAM 不同（約 970 MiB 與 1,730 MiB），其他應用程式並未凍結，因此不能把全部差額都歸因於單一參數。這輪仍提供同機、同權重、同負載下可行的改善證據；不等於長期容量保證。資源是定期取樣，GPU 指整張顯示卡，不是單一模型，也不保證捕捉瞬間峰值。

## 套用後文字回歸

正式 gateway 的 19 件基礎、6 件個人提示詞邊界、5 件較長合成文字都回傳 200，明確檢查全數通過，並逐項閱讀輸出。這是文字整理驗證，不是語音準確率、盲測或母語翻譯驗收。

此輪檢查發現並修正兩個既有排版問題：

- 「保留成一段文字」未被確定性的單段偏好處理涵蓋，遇到模型自行分行仍會留下多行；現在與「整理成一個段落」一樣處理。
- 未加引號的英文句子嵌在中文中，問號曾被全形化；現在多字英文片語保留其標點，單一產品名仍使用中文句子的全形標點。例如 `你有用ChatGPT?` 整理為 `你有用ChatGPT？`。

[基礎 19 件](evidence/qwen-load-mode/chinese.json) · [個人提示詞 6 件](evidence/qwen-load-mode/personal.json) · [較長文字 5 件](evidence/qwen-load-mode/long.json)。標點／單段偏好 6 項及既有個人化 23 項單元測試也通過。沒有藉由放寬原本測試條件消除失敗。

Breeze 尚未切換成正式模型；自然長口述、中英混說、多人長期負載及 GPU 記憶體餘裕仍待驗證。其他 llama.cpp 版本需先用 CLI 核對載入參數，勿假設舊版本支援 `--load-mode`。
