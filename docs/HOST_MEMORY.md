# 主機記憶體與翻譯逾時

2026-09-30 的本機文字翻譯探測發現：翻譯模型 `/health` 回傳 HTTP 200、`status=ok`，但短句「請幫我生成一個計劃，等我提供資料後再開始。」兩次請求均超過 120 秒而逾時。第二次在一般主機權限下重測仍失敗，因此不能將結果只歸因於工具沙箱。

當次觀察到系統可用記憶體約 379 MiB、使用率 97.7%，翻譯 slot 仍處理提示詞。這是記憶體壓力與逾時同時發生的證據，尚非控制變因實驗，不能確定唯一原因。未關閉其他應用程式，也未因逾時直接重啟模型。六句主詞／轉述翻譯比較未完成，新翻譯提示詞未部署。

維護工作現在記錄整台主機的可用及總記憶體，管理摘要新增「主機記憶體」。不足 1 GiB 或低於總量 10% 時顯示注意；缺少、格式異常、採樣失敗及超過 15 分鐘的紀錄亦不顯示正常。這是提醒門檻，不是容量保證，也不會自動停止程式、改模型或拒絕使用者工作。

23 項維護與管理摘要測試通過，含低記憶體、相對比例、異常值、舊紀錄及採樣失敗時清除舊值。仍需在資源恢復後完成真實短句及長句翻譯比較，並驗證多人／日常其他程式同時使用的容量。健康端點表示服務能回應，不能代替實際推論延遲驗收。
