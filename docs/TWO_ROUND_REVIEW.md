# 0.6.0：兩輪產品修正

日期：2026-09-22。使用者要求用 Steve Jobs 與 Elon Musk 兩種思考角度檢視並修正。本文件只描述本專案採用的「簡化操作」與「找出失敗原因」方法，不代表兩位本人的意見或背書。

## 第一輪：第一次打開就知道怎麼用

問題：首頁把帳號、設定、私人金鑰並列，新使用者需要先理解架構才能選按鈕；登入欄位輸入後，原提示文字消失。

已修改：首頁依狀態顯示登入／麥克風／啟用鍵盤三步中的下一步；私人連線收進「帳號與連線 → 進階：私人電腦連線」。登入欄位加入常駐標籤及可讀名稱，保留單一主要動作。觸控按鈕維持至少 48dp，黑白樣式沿用。

驗證：Android 全套編譯與簽章驗證通過。尚未在 Pixel 9 做視覺、TalkBack、大字體或觸控驗收；不以編譯通過宣稱使用者已驗收。

## 第二輪：失敗後不要立即丟掉錄音

問題：0.5.0 的「取回上一筆」只能找主機已收到的工作。上傳前就斷線時，手機會刪除音檔，必須重講。

已修改（限帳號模式）：

- 錄完後先把一份錄音用 AES-GCM 加密，放到 App 的 no-backup 私有目錄；金鑰使用 Android Keystore。
- 未完成時保留同一個請求代碼。主按鈕顯示「重試上一段」，不直接覆寫成新錄音。鍵盤「更多 → 刪除保留錄音」可清除。
- 成功後清除；登出／清除登入／切換帳號會清除；超過一小時不可重試，下次檢查時刪除過期檔案。App 沒有在關閉狀態安排背景定時刪除。
- 只保留一份，音訊最多 2 MB；有效期及請求代碼與密文一起驗證，密文被修改不能正常解密。登入識別及主機不同時不共用音訊。
- 已成功或正在處理的相同錄音重送，沿用原工作，不再次辨識或扣量；設定改變也不改寫原工作使用的偏好。
- 只有明確手動重試才重新處理已失敗的工作；成功後計一次用量。新工作依當時帳號額度限制。
- 清除結果時比對請求代碼，避免舊工作晚回來，誤刪新錄音。

伺服器仍不永久保存录音／文字。錄音開始到封裝完成期間仍有 App 私有的短暫原始音檔；正常送出流程結束後刪除。加密暫存不能保證涵蓋錄音尚未完成時的程序被殺、裝置斷電、儲存失敗或金鑰失效。

## 驗證證據

- 18 項 Python 測試通過，新增成功重試不重扣、偏好修改不影響原工作、明確重試失敗工作等檢查。
- Java 加密檔案測試通過：音訊往返一致、密文不含原始音訊、竄改拒絕、請求／登入隔離、過期清除及大小上限。
- Java HTTP 故障注入回歸通過：503 可重查，401 停止重試，不自動重送錄音。
- 實際 Whisper／Qwen 與 Cloudflare HTTPS 測試：同一錄音再次送出，文字相同、用量不變；不是 Pixel 9 或 Android Keystore 實機測試。
- APK 0.6.0 沿用原套件與簽章，v2/v3 驗證通過。

## 仍有的限制

- 一小時內若主機已完成工作但結果因重啟／15 分鐘過期而消失，同一請求目前不重新計算已成功的工作；重試可能仍顯示結果過期。這個交付確認缺口尚未解決，不能宣稱任何情況都不會白講。
- 登入過期後重新登入會清除舊登入的暫存，未完成錄音不會跨帳號／登入自動移轉。
- 私人金鑰模式維持舊行為，不提供本次加密錄音重試。
- Pixel 9 真機的 Keystore、原子檔案寫入、App 被關閉後恢復、長錄音與 Surfshark／行動網路仍待驗收。
- 臨時網址、家用主機可用性、模型中文品質、長期容量、商店付款仍是後續工作。

手機測試順序：登入 → 錄一段 → 暫時關閉網路 → 確認出現「重試上一段」→ 恢復網路 → 重試並確認用量只算一次 → 測試手動刪除及換帳號後不殘留。
