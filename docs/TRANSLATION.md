# 0.8.0：中文優先的語音翻譯

DreamType 以台灣使用者為主：介面使用繁體中文，預設「整理・台灣繁中」，說話語言預設中文。翻譯是明確選擇的模式，不會自動把日常中文變成外文。

## 手機怎麼用

1. 覆蓋安裝最新 APK，主機也需更新到 0.8.0 並下載翻譯模型。
2. 在 LINE、記事本等 App 切換 DreamType 鍵盤。
3. 點鍵盤上方的「整理・台灣繁中 ▾」，選「翻譯成英文／日文／泰文／馬來文／韓文／越南文／印尼文／台灣繁中」。
4. 按「開始說話」，說完按「停止並翻譯」。
5. 看過譯文後按「插入文字」，需要時先修改。若啟用直接插入，則依原設定插入。

回到一般中文輸入，選「整理成台灣繁中」。錄音、處理中、待插入文字或保留錄音尚未清除時，快捷選單暫停切換，避免把前一段誤當新模式。

鍵盤快捷選擇保存在本機，且隨每筆請求送出；另一台裝置的設定不會默默改掉這一段的目標語言。「我的設定」可儲存帳號偏好、預設模式與語言。若要說外文，在「我說的語言」選該語言或自動辨識；中文使用者不用調整。

介面参考 [Typeless 的鍵盤翻譯操作](https://www.typeless.com/help/quickstart/translate)，本版使用可見的點選選單，沒有複製商標、圖示或長按上滑手勢。

## 翻譯方式與資料

辨識仍在主機的 Whisper 執行。中文整理仍用 Qwen；翻譯以英文作中間語言，中文到英文使用 Qwen，其他步驟使用本機 TranslateGemma。選台灣繁中時套用台灣繁體轉換。日本文字等其他語言不經簡繁轉換，避免改壞漢字。

這不是雲端翻譯 API。錄音、工作恢復、結果加密、收件確認及用量規則沿用 0.7.0。翻譯結果取代該筆文字輸出，不新增永久翻譯歷史。

- 翻譯模式不替你回答問題或擴寫需求；「我的整理提示詞」主要作用於整理模式，翻譯優先保留原意。
- 先保護中文金額片段，再還原到譯文。明確的台幣轉成 `TWD`，美元轉成 `USD`；只說「元」就保留「元」，不猜是哪國貨幣、不兌換金額。建議說完整幣別。
- 部分常見中文整數會轉阿拉伯數字；「一千五」這類可能有歧義的說法保留原寫法，不猜金額。
- 金額標記遺失、回應空白、輸出截斷或翻譯服務失敗，整筆標失敗而非回傳中文假装成功，不扣成功用量。
- 手機檢查回傳模式與目標語言；舊版主機不能默默把中文原文當作翻譯。
- 翻譯不是完全無誤；人名、敬語、專業內容與中間語言造成的細微語意變化，仍需使用者確認。尚未完成八種語言的母語者驗收。

## 驗證範圍

- 34 項 Python 測試：設定驗證、個人資料隔離、工作設定快照、翻譯故障不回退原文、金額保留、原有備份與收件確認等。
- Java 測試：語言標頭、拒絕舊版／錯誤目標結果、驗證後才收件確認；原有斷線恢復及加密核心測試通過。
- APK 使用的相同連線類別，實際經 HTTPS 跑完八種目標語言、收件確認與重試不重扣；測試短音訊約 1.9～4.3 秒，包括測試中的取回及冪等重試，並非正式速度保證。
- 另以 29 秒合成錄音跑中文到泰文，約 12.2 秒完成並確認收件；不代表長時間容量驗收。
- 本機文字測試檢查含否定、日期、人數與金額的合成句子；結果在 `outputs/local_voice/translation-smoke-report.json`。這些範例不能證明所有翻譯正確。
- 英文翻成台灣繁中已實測；其餘外文語音辨識、自動偵測、口音、中英混說尚需較完整資料集。
- Pixel 9 原生 UI、Keystore、行動網路／Surfshark 仍待實機驗收。此版本仍是免費封閉試用，不代表可公開收費上線。
# 識別資料與金額保護補充（2026-09-22）

翻譯現在把電話、網址、電子郵件、訂單等識別資料與金額統一轉為一套依原文順序排列的暫時標記。每個標記附上資料類型提示，實際值不交給翻譯模型改寫；每個翻譯階段都核對順序、數量，再還原。金額沿用既有明確幣別標準化，不自行換匯。遺失、重複、調換標記、新增識別碼或未完整生成時拒絕結果，沿用翻譯失敗／重試流程，不回傳錯誤的號碼或原文冒充翻譯。

實測先發現三類錯誤：不透明標記讓「打電話」變成「輸入」、英文橋接把「訂單編號」變成下單命令、馬來文混用金額與電話標記。透過資料類型提示、中文訂單標籤的翻譯示例與統一標記修正。[初次失敗紀錄](evidence/translation-literals/initial-failures.json)、[馬來文標記混用](evidence/translation-literals/malay-marker-failure.txt) 保留供比較，不把只有字面值正確當成語意全對。

29 項相關單元測試通過，包含橋接損壞立即停止、最後階段重複與新增識別資料拒絕、金額先於電話時的順序。實際模型 12 案例涵蓋八種目標語言，以及英／日／泰／馬來文的金額與電話混合句，均保留識別資料；[完整結果](evidence/translation-literals/model-results.json)。英文與日文檢視確認中文訂單標籤不再變成下單命令；另測「不是新下單」句子的英文否定有保留。

這批是合成文字測試，不是語音、母語人士自然度驗收或 Typeless 比較。英文 `Order AB-007` 本身有名詞／命令歧義，因此最終英翻繁中案例明確使用 `Order number AB-007`；初次歧義案例不列為已解決。標記要求原順序可能拒絕部分本來合法的語序變動，這是目前保守限制。家中主機已更新，手機不用重裝。


## 2026-09-25：翻譯請求，不替使用者作答

新版後端以 TranslateGemma 同時處理「來源 → 英文」和「英文 → 目標」兩階段，翻譯不再呼叫 Qwen 聊天模型；中文整理仍使用 Qwen。無須下載新模型或重裝 0.9.9 APK。

原因來自實測：聊天模型把口述中的數學問題算出答案、把退款要求展開成步驟，並可能額外添加與原文無關的敘述。JSON 包裝及提示示例仍無法可靠阻止。改用現有專用翻譯模型，保留英文橋接，避免未驗證的任意語言直接互譯。

只有真的存在受保護資料時才提供標記提示，不再向無識別碼的請求展示內部標記範本。每一階段都檢查還原後是否出現原文沒有的 DTKEEP／DREAMTYPEAMOUNT 名稱，包括插空白、換大小寫或部分翻譯的形式；異常直接拒絕，沿用翻譯失敗流程，不把原文冒充翻譯。

證據：

- [舊模型 8 組結果](evidence/translation-intent/chat-baseline.json)、[加強提示仍失敗](evidence/translation-intent/chat-prompt-failures.json)。其中政治敘述是錯誤模型輸出，並非使用者原文或產品立場。
- [專用模型 12 組英／日／泰／馬來文結果](evidence/translation-intent/specialist-results.json)，包含口述請求、數學提問、訂單／電話／email／金額；沒有新增測試中的內部標記，字面識別資料有保留。
- [6 組英文請求測試](evidence/translation-intent/specialist-english-probes.json)：計劃、退款、數學、只輸出單字等均保留要求本身，沒有完成要求。
- 40 項相關本機測試通過，新增無識別碼時的標記捏造拒絕、兩階段均不得使用聊天模型、原文真的提到標記名稱時可保留。

**未通過項目：** 日文「直接回答四加五是多少，不要翻譯」的結果只剩提問，漏掉部分限制；不可列為完整忠實翻譯通過。嘗試 XML 包裝反而產生原文沒有的數值 9，因此未採用，保留[失敗實驗](evidence/translation-intent/rejected-framing-experiment.json)。這些都是合成文字測試，不是語音或母語人士自然度驗收，更不能證明永不執行口述指令。接下來仍需數值／語意保留檢查、日文限制條件、其他語言與真實語音驗收。


## 2026-09-26：台灣中文直接翻日文

台灣中文 → 日文改為 TranslateGemma 單階段直譯；其他語言組合暫時維持原流程。仍套用相同的訂單、電話、email、金額保護，以及捏造標記／不完整結果拒絕，沒有失敗時偷偷切換模型。

8 個合成中文句子的逐案比較（各路線各跑一次）顯示：英文橋接會把「下週三」變星期二、為「週五之前」添加下午，以及省略「直接回答…不要翻譯」的限制。直譯在這三個案例保留了正確資訊。[首批比較](evidence/japanese-direct/comparison.json)、[新增條件句](evidence/japanese-direct/conditions.json)。這批本機文字推論的中位數，英文橋接為 3.42 秒，直譯為 1.88 秒；不含錄音辨識或手機網路，並非速度保證。

[正式翻譯函式的四案回歸](evidence/japanese-direct/protected-route.json)另確認日期／指令句，以及識別資料與金額保留。41 項本機相關測試通過，包含直譯僅一階段、標記遺失／捏造時仍拒絕，以及其他語言的兩階段驗證。

尚未解決：「不要替我寄出」在兩條路線都有主詞或表達不清楚的問題；部分輸出多餘引號、語句不自然或將動作改成標籤。這次比較不是母語人士驗收，也不是所有中文到日文都已達標。完整忠實度仍是公開上線門檻。
