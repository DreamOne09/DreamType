# 已確認送達後的暫存損壞

2026-09-28：檢查重試時確認 jobs 外鍵連動會刪除舊 results、receipts 與 pending_audio，沒有發現舊收件確認殘留。但發現另一個差異：暫存結果解密失敗會無條件把工作改為 failed，即使手機已確認收到文字。這與既有已收件結果自然過期仍保持完成／用量的規則不一致。

現在結果損壞時移除不可讀暫存，但只在没有確認收件紀錄時將工作改為 failed 並釋放額度。已確認者保持 done，取回 API 顯示 expired，同一請求即使帶重試旗標也不重新推論。沒有更改既有送達計費時點、使用量算法或增加付費功能；只是讓故障路徑與原本過期路徑一致。

測試先重現「已收到但被改成 failed」的錯誤，再驗證修正。新增涵蓋已送達的損壞副本維持一次用量、不重新執行；未送達副本損壞釋放額度，重試須有新的未確認收件紀錄，重複收件確認也只計一次。API 測試要求已送達損壞副本回傳 expired、重送仍不再次呼叫 provider。

測試全部使用暫存帳號與人工破壞的測試資料庫，沒有破壞正式資料或調整真實使用者額度。這不證明硬碟永不損壞，也不延長結果的 15 分鐘取回期限。手機不需更新。
