# 登入與撤銷的一致性

登入先計算密碼雜湊，再建立 session。原本兩步之間若發生密碼變更、管理者重設、停用或帳號刪除，登入仍可能使用先前讀取的帳號狀態建立憑證；帳號刪除則可能造成外鍵錯誤。

現在密碼計算仍在寫入鎖之外執行，避免長時間占用資料庫。建立憑證前，在同一個 SQLite `BEGIN IMMEDIATE` 交易中重新讀取帳號，確認仍存在、仍啟用、salt 與密碼雜湊未改變，再建立 session。任何一項不同均回傳相同的登入失敗訊息，不透露是否遭停用或刪除。

如果登入交易先完成，後續的密碼重設／停用／刪除會撤銷該 session；若管理操作先完成，登入不能利用舊狀態發出新 session。這項修正不會終止已經通過驗證、正在執行中的所有 HTTP 操作，也不等於完整的獨立安全審查。

驗證在密碼計算完成與發出 session 之間，分別插入改密碼、一次性重設、停用與刪除，確認舊登入失敗、session 數為零、舊 token 無效，而更新後的密碼仍能登入。相關測試已納入 CI；本機完整 56 項測試通過。
