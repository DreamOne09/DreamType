# REA 研究與 DreamType 整理升級

2026-10-18。本批將既有整理候選整合到服務，並改善 Android 上傳等待提示；不代表商用或商店驗收完成。

## 研究來源與可知範圍

官方 REA 專案為 https://github.com/morluto/rea ，工具採 MIT 授權。實際使用 npm 已發布的 `rea-agents@6.5.0`，不是 GitHub 尚未發布的 6.6.0。Typeless 公開功能說明：https://www.typeless.com/ 。官網把 Dictate、Translate、Ask anything 分開；DreamType 維持使用者選定的「預設忠實口述、不代為執行」範圍。

使用 REA 對本機已安裝的 Typeless 做靜態分析，沒有執行解包腳本、讀取個人歷史、使用私人 API 或複製專有程式碼。先前文件提到的其他 fork 不能代替官方來源。

- 錄音分段 worker、Opus worker、preload 三檔：34,833 bytes，5,733 AST nodes，沒有解析失敗。證據 ID `ev_e0ad9d866eb0b8a44afb12e827a95bf79ee450e7db74016df0a9eacfdb512389`。
- 主程序：625,844 bytes，117,163 AST nodes，觀察到 2 個視窗建立點、35 個 IPC 操作，其中 32 個動態通道。證據 ID `ev_8ba9936a97a2786ad8cb7a358eb5ce6717930ce201674e838327b9dda6f71c91`。
- 樣本的三個 unpacked 原生模組和 ASAR 宣告的雜湊不一致。分析明確標記 observed bytes 為不可信，未執行它們；不能推論是惡意或檔案完好。
- 選定檔案之外仍有大量未分析內容，混淆／動態通道使關係不完整。靜態節點不證明執行時行為，更不揭露雲端模型、prompt 或 Android 實作。

結論：REA 適合定位客戶端的功能邊界，不是可直接替代 Typeless 的服務。研究支持把錄音、傳送、結果操作分開審查；具體實作仍以 DreamType 自己的故障與驗收證據決定。原始分析檔僅留本機，不放入公開 repo。

## 已實作及部署的整理引擎

`outputs/local_voice/organizing` 是普通 Python 模組，不需 `scripts/`、執行時 AST 擷取、`exec` 或全域函式替換。模型 completion 由呼叫端注入，保留不同文字供應商的接點。

- 整合既有候選的英文詞序、引文、識別碼定位及明確改口處理。
- 完整且順序正確的識別碼可保留原字詞位置並接受正常標點編輯；缺失識別碼恢復仍要求更嚴格的來源證據。
- 模型作答、改掉否定或編號時，沿用語音路由的原文加 warning；不能把退回原文算成成功整理。
- 翻譯仍委派原處理器，未知模式拒絕，不增加「執行指令」模式。
- 每次請求持有自己的詞庫與標記表，取消和 provider 錯誤正常傳遞。

已在屋主服務進行窄範圍部署，保留 server 回復檔；資料庫仍是原 live schema 4，沒有部署付款候選。固定 HTTPS health 回報 `organizer=faithful-v1`，未登入 `/v2/me` 仍為 401。私人文字 API 實測「請幫我生成一個計劃。」保留原句。

## 驗證與限制

8 項新引擎／整合測試通過；既有 organizer candidate、個人偏好、保真、台灣標點和改口回歸通過。六筆合成文字分別走既有候選與新模組，兩者全部接受且逐筆結果相同：口述命令、訂單改口、中英混合、引文、識別碼、商務列點。這證明交付整合保持既有行為，不是新模型準確率提升；快取與執行順序不同，不能據此宣稱加速。

Android 改為分塊寫入音訊並顯示實際傳送進度；傳送與等待服務確認分開，百分比不代表辨識完成。22 組 JVM 通訊／恢復契約通過。rc11/code40 APK 已用原維護者簽章建立；未安裝 Pixel 9、未發布 Release，沒有宣稱實機手勢或 TalkBack 已驗收。此本機候選不是 Play 付款建置。
