# 翻譯人稱與指令驗收

2026-09-30。本文件記錄尚未修好的語意問題，不代表翻譯品質已達公開上線門檻。

## 固定比較方法

`tests/quality/translation-roles.json` 是自造文字案例，包含語意驗收要求，沒有真人錄音或客戶資料。比較所有模型時使用同一份原文。英文、日文、泰文、馬來文都應逐案檢查；此批實際結果只有英文，不推論其他語言。

判定以語意為準，不要求完全符合某個英文答案，也不能只看是否出現 I、you 或否定字。每案檢查：誰做動作、誰提供資料、要求或承諾、否定範圍、先後條件、是否新增收件人、是否執行口述指令。缺少其中一項即不可列為完整通過。未完成或格式不符另列錯誤，不能刪除後只算成功率。

## 本機實驗結果

`docs/evidence/translation-roles/` 保留三種未採用方案：TranslateGemma 加人稱提示、Qwen 校對現有翻譯、Qwen 直接翻譯。原始回覆保留，不能把輸出中的 `target` 偷改成期望的 `translation` 欄位來宣稱格式通過。

- TranslateGemma 原本把「不是請你現在寄」翻成不是請「我」現在寄；增加人稱提示仍未修正。
- Qwen 校對仍保留第三人称案例的錯誤，第一案還把提供資料的「我」改成「你」。不能增加一個校對步驟就宣稱更可靠。
- Qwen 直接翻譯修好部分人稱，但 `recipient-wait` 新增原文沒有的「寄給我」，`quoted-request` 把引用內的要求改成「我會開始」。12 案中只有部分回覆使用要求的 `translation` 欄位，其餘使用 `target`。
- 直接翻譯的個別文字請求耗時約 0.3 至 86 秒。期間觀察到主機可用記憶體約 291 MiB，但這只能說明同時存在記憶體壓力，不能證明延遲全部由記憶體造成。此時間不含語音辨識及手機網路，也不是供應商公平速度比較。

三種方案均未部署。現有 TranslateGemma 路線仍有上述語意缺陷，維持現況不代表問題已解決。

## 切換前必須完成

1. 新模型先跑固定案例，再用未參與提示詞調整的新句子驗證，避免只記住答案。
2. 保留模型版本、完整提示、生成參數、失敗與未完成結果；比較時區分模型原始輸出與產品標記還原結果。
3. 經正式翻譯函式重測電話、金額、訂單、標記、非完整生成拒絕，以及不執行口述指令。
4. 日／泰／馬來文由能理解原文與目標語言的人檢查人稱、條件、敬語與自然度。
5. 在 Pixel 9 行動網路與 Surfshark 下驗證完整錄音到插入流程。單句模型成功不能替代手機驗收。
