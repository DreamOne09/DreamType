# 順序詞漏字保護

2026-09-28：對 60 個既有合成文字案例跑完整回歸，原有明確檢查全部通過，但人工比對發現「第一明天先去銀行領錢」被整理成「明天去銀行領錢」，漏掉「先」。[當時報告](evidence/chinese-regression-20260928.json)保留原檢查結果，不能將全綠解讀為完整語意無誤。

把「先、再、然後、最後」加入既有字面忠實度檢查，使用序列對齊拒絕刪除或搬移這些詞；不只比較出現次數。仍允許列舉標記轉換、標點與排版。這是保守字面檢查，可能拒絕合理同義改寫，並非完整語意解析。

補上該清單案例的 `required`，要求完整「明天先去銀行領錢」。[保護後八例](evidence/order-cue-guard.json)中該例回傳 503，其餘七例通過：保護成功攔下不忠實結果，但模型漏字本身尚未修復，**不能宣稱八例整理成功**。語音路徑已有整理錯誤時返回辨識原文與警示的處理；文字整理端點則回傳 503，沒有偽造成功。

16 項忠實度、6 項改口與 25 項個人設定／路由測試通過。新負例包括刪去「先」、將「先」移到另一動作，以及刪除「然後／最後」。這些測試不是 Pixel 9 或自然語音驗收；後續需改善模型保留順序詞，並重跑更強的明確檢查。

## 清單生成修正

針對已被判定為明確列舉的輸入，在既有清單提示中區分「第一、第二」列舉標記和「先、再、然後、最後」動作順序，並加入不同於測試內容的收件人／附件範例。沒有個人格式時才啟用該提示；原本的順序詞拒絕檢查保留，沒有降低門檻或新增一輪模型呼叫。

[八例段落](evidence/order-cue-list-prompt.json)全部成功，原失敗清單現在保留「明天先去銀行領錢」。[完整 60 例](evidence/order-cue-list-regression.json)使用補強後的要求全部回傳 200 並通過明確檢查，涵蓋台灣名稱、電話、改口、條件、個人格式與語句順序。人工再檢查目標清單及較長的改口清單，確認順序詞與整份清單共用條件保留。25 項個人設定／路由測試亦通過。
