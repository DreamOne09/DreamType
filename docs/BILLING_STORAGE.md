# 付款儲存與遷移準備

目前正式服務仍使用 schema 4，付款尚未啟用。`billing_migration.prepare_storage` 是明確呼叫的離線準備函式，不會在匯入、一般啟動或未設定付款時自動執行；目前也沒有提供一般管理頁或 CLI 入口。**完整付款生命週期與部署設定尚未驗收前，不應在正式主機執行。**

## 遷移保護

1. 要求既有 schema 4，拒絕未知版本、部分付款資料表、資料庫完整性錯誤。
2. 檢查同一安裝的 uvicorn 程序，存在時拒絕；不會擅自終止服務。維護鎖防止排程重啟，SQLite 寫入鎖防止備份與遷移間的資料變更。操作人員仍須確保其他服務管理程式不會自行啟動主機。
3. 有排隊、處理中錄音、待處理音訊或未確認收件時拒絕；先完成或取回工作。
4. 持有寫入保留鎖時建立加密備份，由既有備份工具完成記憶體還原驗證後才繼續。備份不含錄音、逐字稿與登入 session。
5. 所有新增資料表與版本號在同一 SQLite 交易中提交，不使用會打斷交易的 executescript。例外或程序突然結束時回滾。
6. 升級只準備 schema 9 資料表，不啟用付款、不變更帳號額度。再次執行拒絕，避免把未知既有 schema 9 當作這次升級成功。

舊版 schema 4 Store 會拒絕開啟 schema 9。新版 Store 可開啟明確準備完成的 schema 9，仍不會自行遷移；帶入付款政策前必須已完成離線準備。升級成功後只能使用經驗證的付款版服務；如需退回，將遷移前備份和最新刪除紀錄還原到新目錄再切換，不原地調低版本或覆寫資料庫。還原會撤銷 session；舊快照不能代表升級後新增的帳號／交易，正式回復策略仍需配合上線停機窗口。

## 購買金鑰與備份

`billing_crypto.BillingCipher` 使用獨立的 `work/beta/billing.key`，購買憑證的加密驗證範圍綁定帳號與憑證雜湊。已有購買資料但金鑰缺失時拒絕重新生成，必須取回原金鑰。

存在此金鑰時，加密備份內層使用 format 2，包含同一份金鑰；舊 format 1 仍可還原。外層仍由另外保管的備份復原金鑰加密。只接受固定成員清單、正確金鑰長度，以及完整 schema 9 結構；部分遷移資料庫拒絕備份／還原。

schema 9 還原前逐筆驗證購買憑證的解密及雜湊；缺失、錯誤金鑰或損毀憑證拒絕安裝。還原的訂閱標記為必須重新驗證，清除舊重試排程，不憑舊快照直接發放額度。SubscriptionPolicy 已在 Store.reserve 強制此要求；實際服務仍未配置付款政策。

記憶體驗證與實際還原使用相同的隱私檢查，通過後才建立目的資料庫或寫出主機金鑰。不得把 billing.key、備份復原金鑰或加密備份提交 Git。

## 演練證據與限制

`test_billing_migration.py` 使用 TemporaryDirectory 合成安裝，涵蓋帳號與偏好保留、加密備份還原、第一個 DDL 後失敗、版本號變更後程序突然退出、備份失敗、錄音未完成、主機在線與未知 schema 拒絕。

`test_billing_crypto.py` 驗證憑證內容不出現在備份明文、跨帳號／內容竄改拒絕、金鑰缺失不重生、schema 9 還原與強制重新驗證，以及金鑰錯誤時不發布備份。

這是本機隔離演練，不是正式資料庫升級或異機災難還原驗收。正式啟用前還須完成帳號權益交易、服務端付款生命週期、Android 商店測試與離機復原金鑰保管。
