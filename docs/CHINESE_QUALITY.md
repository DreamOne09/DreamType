# 台灣中文品質驗收

目標是讓台灣使用者放心口述，不能以「有回傳文字」等同正確，也尚不能宣稱品質超越 Typeless。

## 2026-09-22：避免截斷中文整理

原本整理服務只檢查回傳文字是否非空。模型即使因輸出上限而中途停止，也可能把半段文字當成成功結果。

現在只接受模型明確正常完成（`finish_reason: stop`）的整理結果：

- 語音路徑保留完整辨識原文，回傳 warning；現有 Android 鍵盤顯示「排版暫時失敗，已保留辨識原文」。
- 純文字整理端點回傳 503，不交付半段文字。
- 這保護的是「模型有回報截斷」；不能偵測模型正常結束但自行漏掉內容，也不保證語音辨識本身沒有漏字。

驗證：36 項 Python 測試通過，包含 length、content_filter、缺少結束原因三種不完整結果，以及正常完成結果。更新家中服務後，實際 HTTPS Android Java 測試通過登入、偏好、排隊辨識與用量流程（短測試 3.77 秒）。並非 Pixel 9 實機驗收。

## 下一階段仍須驗證

可重跑的 19 個合成文字案例在 `tests/quality/taiwan-chinese.json`，涵蓋日期修正、金額、條件、地名、人名、中英夾雜、列舉與識別資料。用 `scripts/check_chinese_quality.py --output work/chinese-report.json` 在已啟動的本機服務執行。文字及結果皆為人工編寫的合成資料，非使用者錄音。HTTP 200 不等於語意正確，需閱讀輸入與輸出。

本輪發現模型會把電話 `0912-003-456` 寫成少一碼。現已比較整理前後的結構化識別資料（電話、網址、信箱、部分英數訂單格式）及出現次數；不一致時拒絕整理結果，語音路徑保留原文。這不涵蓋所有識別碼格式、口述數字或辨識階段的錯字。含明確修正的識別碼也可能退回原文，寧可請使用者確認，不推測其意圖。

第一輪文字報告有 11 件回傳文字，1 件因識別資料變動被拒絕。後續加入逐次請求的識別資料替換：模型只整理含暫存標記的文字，標記需各出現一次且保持順序，才放回電話等原值，再次驗證識別資料一致。映射不跨帳號或請求共用，也不持久保存。

40 項 Python 測試通過，包括標記遺失、重複、順序改變、未知標記、原文含相似標記的碰撞，以及真實格式化函式的回填／失敗保留路徑。實際模型的原電話案例與雙信箱、雙電話、帶編號清單均能整理並保留原值；明確改口更換編號的案例仍會被拒絕整理，供使用者確認原文。

最新文字報告為 `tests/quality/taiwan-chinese-report.json`。現在檢查每個案例的指定關鍵內容，清單案例另外檢查項數、共用條件獨立一行，反例要求名稱／名次／時間保留且不轉條列。16 件的指定檢查通過；這些檢查只覆蓋列出的條件，**不是所有語意與排版品質全部通過**，也不是與 Typeless 的比較結果。

## 明確口述清單

預設整理對從「第一」開始、依序連續且位於句首／標點後的列舉，加強逐項「• 」排版提示。姓名、名次、日期、銀行名稱等延續詞排除；有個人提示詞時不加這項預設提示，讓個人格式保持優先。這是保守的提示啟用規則，不會直接用規則刪字，也不保證涵蓋所有說法；缺乏標點、跨項或十項以上仍交給原整理提示。

實驗中單純加強全域指令會把「第一銀行」誤成「第一天銀行」，因此沒有部署該方案。上述條件式處理已通過實際模型的銀行／名次／日期反例及口述修正清單；完整 Python 測試 41 項通過。還需要更多未用於調整的口語錄音驗收。

## 仍待驗證

- 台灣地名、人名、公司名與中英夾雜，不能只靠文字提示詞測試替代真實口音錄音。
- 自我修正、否定、日期、金額與共用條件，在長篇整理後仍完整。
- 個人提示詞只調整文風，不能擅自替使用者回答問題或新增需求。
- 同一批取得同意的錄音與 Typeless 做盲測，比較錯字、漏意、修正時間及延遲，才有「更好用」的證據。
- Pixel 9 的鍵盤高度、單手操作、App 切換、Surfshark 行動網路與加密重試仍待實機驗收。

目前仍是封閉試用；商店、付款、固定入口與備援等差距另見 [正式使用差距](PRODUCTION_STATUS.md)。

## 個人格式與台灣文字轉換（2026-09-22）

個人排版偏好放在提示最後，明確優先於預設範例；一段話不可換行、數字編號不可改成圓點，仍須保留事實與條件。新增單段、數字清單及圓點清單三個合成案例。

OpenCC 改用 s2tw，僅轉換繁體與台灣字形，不再用缺乏上下文的詞組轉換把「拿文件」改成「拿檔案」。台灣用語由整理模型依上下文處理，並不保證所有詞彙都正確。

本次 60 項 Python 測試通過；重啟服務後，19 個實際模型文字案例的指定檢查通過。這不是語音辨識、Pixel 9 實機或完整語意品質驗收。

## 較長語境的獨立文字驗收（2026-09-22）

新增 `tests/quality/taiwan-long-context.json`，於既有提示與模型未再調整的情況下測試五種較長語境：雙條件才出貨、改早上時間但保留下午會議、轉述錯誤與否定、總額和每人金額、口述給工程師的要求。結果保存於 `taiwan-long-context-report.json`。

五件指定檢查通過；逐筆閱讀結果確認上述條件及區別仍保留，沒有把口述工程需求當成需要執行或回答的指令。當次本機文字端點耗時 0.67～0.89 秒，不包含錄音、ASR、手機網路或同時多人使用。此為合成案例，既已加入專案，後續應視為回歸資料，不再視為全新的盲測集。

重跑：`python scripts/check_chinese_quality.py --runtime-root <服務根目錄> --cases tests/quality/taiwan-long-context.json --output <報告路徑>`。`--cases` 可指定其他人工編寫的案例集；預設仍跑原本的 19 件基礎案例。請勿將真實個人錄音或私人訊息直接加入公開 repo。

這些證據仍不能支持「中文品質已優於 Typeless」；需要台灣使用者的真實口述，以及同批音訊、同樣情境的比較。

## 無語音時不產生文字（2026-09-22）

新增 `scripts/check_no_speech.py`，對實際 ASR 服務送出三段各四秒、16 kHz 單聲道的合成音訊：數位靜音、固定亂數低振幅雜訊、60 Hz 低頻音。三者皆回傳空字串，未出現模型憑空補出的字幕。另使用既有短語音作正向對照，取得非空辨識結果，避免把全數拒絕誤當通過。

報告在 `tests/quality/no-speech-report.json`。對照音訊與文字不寫進公開報告，只保存是否非空及字數；本輪不改 VAD 或模型參數。

重跑：`python scripts/check_no_speech.py --runtime-root <服務根目錄> --speech-control <已知有語音的測試檔.m4a> --output <報告.json>`。這會讀取本機服務金鑰並送到 localhost，不使用手機麥克風或外部語音 API。

通過只代表這三個簡單非語音訊號被排除，不涵蓋街道、人群、音樂、電視人聲或真實手機底噪，也不能證明安靜說話時不會漏字。
# 台灣電話字面值保護補充（2026-09-22）

整理階段擴充電話文字保護，涵蓋 `02-23456789`、`(02)2345-6789`、空格分隔手機及 `+886` 國碼等寫法。以一次請求內的標記隔離，完成後還原原本數字、括號、空格及連字號；不自動補國碼，不查詢號碼是否真實有效。若模型遺失、重複或調換標記，拒絕套用整理結果。

實際模型預驗證發現一例把「先打」刪除並拆行，雖然號碼還在；因此補強識別碼周圍動作、否定、時間、條件及個人段落偏好的提示。提示是改善手段，不是所有句子語意正確的保證。[修正前結果](evidence/taiwan-phone-literals/before-prompt-fix.json) 保留此失敗，不以只核對號碼宣稱整句通過。

部署前相關 19 項單元測試通過。套用到家中服務、確認 health 的辨識／整理／翻譯／worker 均 ready 後，4 個新增電話文字案例及原有 19 個中文案例均通過明確檢查；輸出已人工閱讀。[電話結果](evidence/taiwan-phone-literals/live.json)、[既有中文回歸](evidence/taiwan-phone-literals/chinese-regression.json)。電話案例保留「先打／如果沒接／再打」及原號碼，並維持指定單一段落。

這只保護**已辨識成文字**的號碼，不能修正語音辨識階段已聽錯的數字；測試為合成文字，沒有新增真實口述準確率或與 Typeless 的比較證據。這次是主機更新，手機不必重新安裝。


## 自訂詞庫的辨識提示額度（2026-09-23）

修正自訂詞提示以字數截短、卻被 faster-whisper 再按 token 保留尾端的問題。新提示用載入模型的實際 tokenizer 計算（包含 initial_prompt 會加上的前導空白），限制 200 tokens；以完整詞條挑選，個人詞庫優先於通用台灣縣市。逗號、頓號、分號與換行可分隔詞條；不截半個人名，重複詞條只保留一次，過長單一詞條跳過後仍嘗試後面的詞條。詞庫仍有辨識提示容量上限，請把最常用詞放前面；不代表 1,000 字設定全部同時送入 ASR。非中文來源也按相同額度挑選詞庫，不加入台灣地名。

使用目前 whisper-turbo 的實際 tokenizer，比較相同合成長詞庫：舊提示 462 tokens，Whisper 保留最後 223 tokens 後不含首項「陳昀霏」；新提示 199 tokens，首項完整保留。[tokenizer 結果](evidence/speech-hint-budget/tokenizer-result.json)。相關個人化、識別碼保護與翻譯合計 32 項測試通過。

依據本機安裝的 faster-whisper get_prompt 實作與 [上游程式碼](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/transcribe.py)：previous_tokens 超長時只保留 max_length // 2 - 1 的尾端。此證據只證明提示內容進入可用額度，沒有以真人錄音比較辨識率，不能宣稱準確率提升多少。此為主機修正，手機不用重裝。
