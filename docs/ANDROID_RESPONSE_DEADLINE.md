# Android 慢速回應限制

原本 `HttpURLConnection` 的讀取逾時限制無資料等待時間，持續收到少量資料仍可能無限延長回應內容讀取。本機 HTTP 重現以每秒一個空白傳送 JSON，15 秒讀取設定仍在約 18.2 秒後成功。

`VoiceApi` 現在對成功與錯誤回應的內容讀取檢查累計 15 秒期限，並將內容讀取的無資料逾時設為 15 秒。期限前開始的一次讀取可能繼續等到該次讀取逾時，所以這不是精確 15 秒硬中斷。最後一筆資料或 EOF 在期限後抵達也拒絕，不解析為成功；原有 1 MiB 大小限制及關閉串流保留。

這不是整個操作的硬期限：DNS、連線、回應標頭、上傳寫入、排隊與收件確認仍有各自流程。三分鐘輪詢上限只在輪詢間檢查。不能據此聲稱手機所有網路故障都有嚴格的端到端時間上限，這部分仍需補強與 Pixel 9 實測。

逾時沿用既有錯誤／讀取重試流程，不新增錄音自動重送，也不改 request ID。帳號模式加密保留錄音與手動重試規則不變。逾時不代表伺服器已取消工作，應使用取回上一筆確認結果。

驗證：九組 JVM 契約測試通過，包含正常繁中、超過期限的內容與 EOF 拒絕、串流釋放及大小限制；既有讀取重試不重送錄音、收件確認、加密錄音與語言契約亦通過。本機慢速 HTTP 情境另行重測。尚未建置新版 APK 或部署至手機，不是原生網路堆疊驗收。
